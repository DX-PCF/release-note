# BigQuery

## Changed
**原文:**
Effective *March 9, 2026*, new users are required to have a Cloud Billing
account to use the BigQuery Migration Service.
This change applies to users starting new projects using BigQuery Migration
Service features, such as SQL translation and migration assessment.

[BigQuery Migration Service](https://docs.cloud.google.com/bigquery/docs/migration-intro)
After *May 18, 2026*, all users are required to have a Cloud Billing account to
use the BigQuery Migration Service.

Pricing for the BigQuery Migration Service
remains without charge.

[Pricing for the BigQuery Migration Service](https://docs.cloud.google.com/bigquery/docs/migration-intro#pricing)

**説明:**
BigQuery Migration Serviceを利用する際に、Cloud Billingアカウントの紐付けが必須となる変更が発表されました。
この変更は段階的に適用されます。
*   **2026年3月9日以降:** BigQuery Migration Serviceの機能（SQL変換、移行アセスメントなど）を利用して新しいプロジェクトを開始するユーザーは、Cloud Billingアカウントが必要です。
*   **2026年5月18日以降:** すべてのBigQuery Migration ServiceユーザーにCloud Billingアカウントの紐付けが必須となります。
BigQuery Migration Service自体の料金は引き続き無料であり、料金が発生するわけではありません。

**影響有無:**
**限定的な影響があります。**
ほとんどのGoogle Cloudプロジェクトには既にCloud Billingアカウントが紐付けられているため、既存の運用において直接的な影響は限定的であると考えられます。
ただし、以下のいずれかに該当する場合は影響があります。
*   BigQuery Migration Serviceを現在利用している、または将来的に利用する予定があるが、Cloud Billingアカウントが紐付けられていないプロジェクトがある場合。
*   特に、無料枠や特定のプロモーションでの利用を想定していたプロジェクトで、Cloud Billingアカウントの紐付けがまだ行われていないケース。

**対処方法:**
*   現在BigQuery Migration Serviceを利用している、または将来的に利用を計画しているプロジェクトについて、関連付けられているCloud Billingアカウントが有効であることを確認してください。
*   もし対象となるプロジェクトにCloud Billingアカウントが紐付けられていない場合は、上記の期日までにCloud Billingアカウントを設定し、プロジェクトに紐付けてください。この変更による追加料金の発生はありません。

**用語説明:**
*   **BigQuery Migration Service**: 他のデータベースシステム（例: Teradata、Oracle、SQL Serverなど）からGoogle CloudのBigQueryへデータを移行する際に、SQLクエリの自動変換や移行アセスメント（移行の複雑さやコストの評価）を支援するサービスです。大規模なデータウェアハウス移行プロジェクトで利用されます。
*   **Cloud Billing Account**: Google Cloudが提供する各サービスの利用料金を管理するためのアカウントです。クレジットカード情報などが登録され、プロジェクトに紐付けられることで、利用料金が請求されます。無料サービスであっても、リソースの不正利用防止などの目的で紐付けが求められる場合があります。

*   **新機能・改善の利用**: 新しいバージョンが提供されたため、機能強化やバグ修正、パフォーマンス改善などを享受できます。
*   **非推奨バージョン利用時の影響**: 現在ご利用のGoogle Cloud Composer2環境は、GKEを基盤としていますが、その基盤GKEがこの"No channel" (非推奨チャネル) の非推奨バージョンを使用している場合、90日以内にアップグレードが必要となる可能性があります。ただし、Composerはマネージドサービスであり、基盤となるGKEバージョンの管理はGoogle Cloudが行うため、直接的な影響は限定的です。

1.  **Composer基盤GKEバージョンの確認**: Composer環境が利用しているGKEバージョンを直接確認することは通常できませんが、Google Cloud Composerのリリースノートやドキュメントで、基盤となるGKEバージョンの更新に関するアナウンスがないか定期的に確認してください。
2.  **GKEバージョンアップグレードの計画**: もし今後、Composer側で基盤GKEバージョンの手動アップグレードが必要になった場合や、非推奨バージョンが利用されていることが判明した場合は、本リリースノートで提示された新しい利用可能バージョンへのアップグレードを計画・実施してください。アップグレード前にテスト環境での検証を強く推奨します。
3.  **自動アップグレードの考慮**: Composer環境の基盤GKEは、Google Cloudによって自動アップグレードされる可能性があります。メンテナンスウィンドウとメンテナンス除外期間の設定が適切であることを確認してください。

用語説明：
*   **GKE (Google Kubernetes Engine)**: Google Cloudが提供するマネージドなKubernetesサービス。コンテナ化されたアプリケーションのデプロイ、管理、スケーリングを容易にします。
*   **リリースチャネル (Release Channel)**: GKEクラスタのバージョン更新頻度と安定性を定義するチャネル。Rapid (最新機能、迅速な更新)、Regular (安定性と最新機能のバランス)、Stable (安定性重視)、Extended (長期サポート) などがあります。"No channel" は非推奨であり、特定のチャネルに属さない古い運用方法です。
*   **コントロールプレーン (Control Plane)**: Kubernetesクラスタの脳となる部分。APIサーバー、スケジューラ、コントローラマネージャなどが含まれます。
*   **ノード (Node)**: Kubernetesクラスタ内のワーカーマシン。Pod（アプリケーションの最小単位）が実行されるVMインスタンスです。
*   **非推奨 (Deprecated)**: 将来的にサポートが終了し、削除される予定のバージョンや機能。通常、代替手段が提供されます。
*   **自動アップグレード (Auto-upgrade)**: GKEクラスタのコントロールプレーンやノードが、Google Cloudによって自動的に新しいバージョンにアップグレードされる機能。
*   **メンテナンス除外 (Maintenance Exclusions)**: GKEクラスタの自動アップグレードやその他のメンテナンス活動を特定の期間停止させる設定。
*   **非推奨API (Deprecated APIs)**: Kubernetesのバージョンアップに伴い、利用が推奨されなくなり、将来のバージョンで削除されるAPI。アプリケーションがこれらを使用している場合、アップグレード前に変更が必要です。
